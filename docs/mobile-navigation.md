# 移动端导航重构

## 结论

移动端不适合继续用「终端页签 / 文件页签 / AI 页签 / 动作菜单」混在上下两栏。底部导航只应承载移动端最高频的一级任务；文件配置、Tab 管理、网络端口、设置等是二级或上下文动作。

## 信息架构

| 层级 | 内容 | 入口 |
| --- | --- | --- |
| 一级 | 终端 | 底部导航「终端」 |
| 一级 | 文件 | 底部导航「文件」 |
| 一级 | AI 工作区 | 底部导航「AI」 |
| 全局动作 | 设置 | 底部导航「设置」（弹框，无激活态） |
| 二级 | 文件浏览与选择 | 文件全屏面板 |
| 二级 | 文件编辑 Tab | 工作区底部的文件 Tab 条 |
| 二级 | 当前 Tab 动作 | Tab 长按 / 右侧动作表 |
| 低频 | 会话、端口、终端组管理 | 顶栏「更多」或既有菜单 |

## 交互规则

- 底部导航固定在移动端底部，包含「终端 / 文件 / AI / 设置」四项。前三项是互斥的一级视图；
  「设置」是动作（弹设置框），永不处于激活态。
- 底部导航是视图切换器：已在目标视图时点击对应项为 no-op（没有可切换的内容），
  这是有意为之，不是失灵。
- 顶栏「更多」不承载底部导航已有的入口（文件面板 / AI / 设置），避免同一动作两处入口。
- 「文件」打开全屏文件面板；再次点击回到上一次工作区。文件面板关闭时，底部导航继续可用。
- AI 工作区是全局页面，不依赖某个容器；打开时收起文件面板。
- 文件 Tab 条只负责已打开文件之间的切换，不再承担「文件面板 / AI 工作区 / 文件编辑器」的全局切换。
- 桌面端保留原有顶部终端 Tab 与底部 VS Code 风格文件 Tab；本次改动只影响 `max-md`。
